# Joyshell 后续版本路线

## v0.1.69：Windows 企业网络访问能力

`0.1.69_build_4` 为企业网络稳定性正式收口构建：ProxyJump 必须沿原跳板链路重连；运行中的转发规则按用户期望状态自动恢复；规则永久归属 Profile，运行时 Session 只作为可空绑定；转发状态、活动连接数和失败原因通过事件实时更新。Local/SOCKS 坚持回环监听，本版本不支持局域网或公网暴露。

本版本面向通用企业网络环境，遵循 OpenSSH ProxyJump、`-L`、`-R` 和 `-D` 的主流语义，不针对单一用户拓扑做特例。

### 单级 ProxyJump

- 目标 Profile 可关联一个跳板 Profile，跳板机为可选项。
- 跳板机与目标机使用独立的连接、认证、主机密钥记录和错误状态。
- 跳板机和目标机可以分别使用密码、本机私钥或 SSH Agent。
- 目标连接必须通过跳板机完成 TCP 通道建立，不能把目标认证信息复制到跳板机。
- 跳板连接和目标连接均须在认证前完成主机密钥校验；任何一方未确认都不得启动终端、SFTP、监控或转发。
- 首版只支持单级跳板，Profile 循环引用和目标等于跳板机时直接拒绝。

### 端口转发

- 本地转发：`-L local_address:local_port:target_host:target_port`。
- 远程转发：`-R remote_address:remote_port:target_host:target_port`。
- SOCKS5 动态转发：`-D local_address:local_port`，首版只支持 TCP CONNECT。
- 每条规则拥有独立 ID、类型、监听端点、目标端点、所属 Session、状态和最近错误。
- 默认本地监听地址为 `127.0.0.1`；绑定 `0.0.0.0` 必须明确提示风险。
- 重复启动同一规则不得创建重复监听；端口占用、服务器拒绝和目标不可达必须返回可读错误。
- 用户主动停止的规则不会因自动重连自动恢复；意外断线后，原本运行中的规则可在安全重连成功后恢复。
- 应用退出、Session 关闭和规则删除时必须关闭监听器、释放端口并清理后台线程。

### 安全、审计和清理

- 所有跳板、目标和转发连接绑定 Session generation，旧连接事件不得更新新连接状态。
- 禁止在日志、审计、数据库中写入密码、私钥正文、Agent 签名材料或转发流量内容。
- 审计记录仅包含规则 ID、跳板/目标主机和端口、规则类型、启动/停止/恢复/失败/清理结果及错误摘要。
- 主连接断开时，转发进入明确的 `Reconnecting` 或 `Stopped` 状态，不伪装为正常运行。
- 每个监听器都必须有确定的 owner，清理操作需要幂等，重复停止和重复删除不能产生悬挂端口。
- 未完成主机密钥确认、认证失败或 Session 主动断开时，不得创建或保留转发监听。

## v0.1.70：Windows 终端体验增强

- 远端 PTY resize 和重连后尺寸恢复。
- 终端搜索、复制、粘贴、全选、清屏和统一快捷键。
- 10 MB 连续输出下保持输入响应和 Session 隔离。
- Windows 本地 Shell，使用原生 PTY，不占用 SSH Session。

## v0.1.71：Windows SFTP 批量能力

- 多选、批量上传/下载和递归目录传输。
- 隐藏文件显示开关。
- 覆盖、跳过、重命名、续传冲突处理。
- 远程文本文件查看和失败任务批量重试。

## v0.2.0：Windows Stable

- 仅承诺 Windows x64 稳定版收口。
- 汇总并稳定 v0.1.68 的安全连接与可靠传输、v0.1.69 的企业网络访问、v0.1.70 的终端体验和 v0.1.71 的 SFTP 批量能力。
- 完成 Windows 安装升级、卸载数据保留、签名准备、崩溃恢复和长期运行回归。
- 不承诺 macOS/Linux 在本版本完成；两平台单独进入后续版本和独立实机验收矩阵。

## 后续跨平台版本

- macOS/Linux 的原生凭据、SSH Agent、PTY、安装包和实机回归独立规划。
- 跨平台版本不得复用 Windows 能力的假设结果，必须分别完成平台测试和发布验证。
