# Joyshell SSH 基础产品开发需求

版本：v0.1
日期：2026-09-02
范围：SSH/SFTP/终端/主机管理基础能力

## 1. 文档目标

本文件记录 SSH 基础产品在 `v0.1.69_build_4` 正式发布后的验收基线，并指导 `v0.1.70` 及后续迭代。目标是把已发布的 Windows 企业网络能力推进到长期运行和跨平台可验证状态。

本阶段**不实现** Agentic Loop、模型 Provider、MCP、插件市场和团队云同步。Agent 相关代码只能作为边界预留，不得阻塞 SSH 基础版本。

## 2. 当前基线

当前已经具备：

- Tauri 2 + React/Vite/TypeScript + Rust 桌面架构。
- `ssh2-rs/libssh2` 真实 SSH 连接。
- 密码认证和本机私钥文件认证。
- PTY、交互式 Shell、xterm.js 终端。
- 多 Profile、多 Shell、标签切换和独立连接生命周期。
- SFTP 浏览、上传、下载、重命名、删除、新建目录。
- 单次传输重试、取消和偏移续传。
- 独立 SFTP/监控 side session。
- CPU、内存、磁盘、网络、负载、进程、运行时间等主机信息。
- SQLite 本地配置和 AES-256-GCM secret store。

当前已完成并进入持续验收：

- `known_hosts` 主机密钥校验、SSH Agent 认证。
- 单级 ProxyJump、Local/Remote/SOCKS5 转发和可靠自动重连。
- 运行中转发规则的断线恢复及 Profile 持久归属。

当前仍未完成：

- 持久化传输队列和应用重启后恢复。
- Windows 本地 Shell 与 v0.1.70 终端体验增强。
- macOS/Linux 同等强度实机验收。
- ProxyJump 断网恢复、混合认证和转发冲突隔离的完整实机矩阵。
- 终端尺寸变化同步。

## 3. 发布门槛和优先级

### P0：稳定版阻塞项

以下是面向 `v0.2.0 Windows Stable` 的剩余稳定版门槛；不影响 `v0.1.69_build_4` 正式版发布：

1. ProxyJump 断网恢复、混合认证和转发 generation 隔离的完整实机矩阵。
2. 系统密钥链优先的敏感凭据存储和迁移回归。
3. 传输队列持久化、应用重启恢复和重连续传。
4. Windows 终端 resize、大输出和本地 Shell 验收。
5. Windows、macOS、Linux 三平台最小回归矩阵。

### P1：核心竞争力

P1 项用于对标 FinalShell、MobaXterm、Tabby、WindTerm：

1. 跳板机/ProxyJump（代码已实现，持续集成验收）。
2. 本地、远程和 SOCKS 端口转发（代码已实现，持续集成验收）。
3. 终端 resize、搜索、快捷键和大输出稳定性（`v0.1.70`）。
4. SFTP 多选、批量、递归传输和远程文件查看。
5. 本地 Shell。

### P2：增强项

以下功能不得阻塞 P0/P1：Mosh、X11、RDP/VNC、串口、云端同步、插件市场、复杂监控历史、移动端、Agent/MCP。

## 4. P0-1 主机密钥和 known_hosts

### 目标

建立与 OpenSSH 相同的基本信任模型，阻止中间人攻击和无提示的主机密钥替换。

### 功能要求

- 首次连接未知主机时显示：主机、端口、算法、SHA-256 指纹。
- 用户确认后写入应用自己的 `known_hosts` 文件。
- 后续连接严格匹配主机、端口和密钥指纹。
- 指纹变化时必须阻止连接，显示旧指纹和新指纹，提供“取消”和“确认更新”。
- 支持删除单条主机记录和查看全部记录。
- `Strict` 为新 Profile 默认策略。
- `AcceptNew` 只能由用户在 SSH 设置中显式选择。
- `InsecureAcceptAny` 必须显示高风险提示，并禁止作为默认值。
- 不得因为未知主机而静默接受连接。

### 数据和接口

- 增加本地 `known_hosts` 存储，格式可兼容 OpenSSH，至少支持明文 host、端口、算法、base64 key。
- 在 Rust 连接握手完成、用户认证前执行校验。
- 增加 Tauri 命令：查询记录、删除记录、确认新主机、确认更新主机。
- 连接事件新增 `HostKeyPrompt`、`HostKeyChanged`、`HostKeyAccepted`。

### 验收标准

- 未知主机不会直接进入 `Connected`。
- 相同指纹可无提示重连。
- 更换服务器密钥时连接必定失败并给出可读提示。
- 取消确认后不创建 Session。
- 单元测试覆盖未知、匹配、变更、拒绝四种情况。

## 5. P0-2 SSH Agent

### 目标

支持开发者和企业环境中常见的密钥代理登录，避免要求用户把私钥路径和口令交给 Joyshell。

### 功能要求

- Windows 使用 OpenSSH Agent。
- macOS 使用 `SSH_AUTH_SOCK`/Keychain 可用的 agent。
- Linux 使用 `SSH_AUTH_SOCK`。
- Profile 认证方式选择 `Agent` 时，连接前检测 agent 是否可用。
- 展示 agent 中的公钥指纹和注释，允许用户选择密钥。
- 未找到 agent、没有可用密钥或签名失败时返回明确错误。
- Agent 登录必须同样支持 SFTP、系统监控和端口转发。

### 实现要求

- 不把 agent 私钥导出到磁盘或 secret store。
- 认证逻辑与密码/私钥文件认证共用 Session 生命周期和错误模型。
- 保留 `AuthMethod::Agent`，删除当前“未实现”短路分支。

### 验收标准

- 三个平台至少各有一个真实 agent 登录用例。
- agent 认证后终端、SFTP、监控全部可用。
- agent 不可用时不会伪装成密码错误。

## 6. P0-3 敏感凭据存储

### 目标

降低本地数据库泄露后的凭据风险。

### 要求

- Windows 优先使用 DPAPI/Credential Manager。
- macOS 使用 Keychain。
- Linux 使用 Secret Service；不可用时才回退到明确提示的本地加密方案。
- 数据库只存 secret reference，不存明文密码、私钥正文或 agent 私钥。
- 迁移旧 AES-256-GCM 数据时保留一次性迁移流程。
- 日志、审计和错误消息不得包含密码、口令、Token、私钥内容。

### 验收标准

- 导出数据库不能直接恢复密码。
- 卸载和升级行为有明确的数据保留策略。
- 单元测试验证 secret 不出现在日志和序列化 Profile 中。

## 7. P0-4 持久化传输队列和自动重连

### 目标

使大文件传输在网络抖动或应用重启后可恢复，达到 WinSCP/FileZilla 的基本可靠性。

### 数据模型

新增持久化 TransferDescriptor，至少包含：

- transfer id、profile id、方向、local path、remote path。
- 文件大小、已完成字节、创建时间、最后更新时间。
- 状态：Queued、Running、Retrying、Paused、Completed、Failed、Cancelled。
- 重试次数、最后错误、远端文件大小和可选校验和。

### 行为要求

- 应用启动时恢复 Queued/Running/Retrying 任务。
- 重新连接 SSH/SFTP 后，从已确认偏移继续传输。
- 本地/远端文件大小不匹配时，必须询问覆盖、重启或继续，禁止静默拼接。
- 自动重连最多使用有界重试和退避，不得无限循环。
- 用户取消是硬停止，保留部分文件和任务记录。
- 任务队列与交互终端线程隔离。

### 验收标准

- 传输中退出应用，再启动后任务仍可见。
- 断网恢复后可继续传输且字节数不回退。
- 目标文件被替换时不会错误续传。
- 取消、失败、重试、完成状态在 UI 和数据库一致。

## 8. P1-1 跳板机和端口转发

### 功能范围

- ProxyJump/单级跳板机。
- 多级跳板机作为后续扩展，不作为首版阻塞项。
- 本地端口转发 `-L`。
- 远程端口转发 `-R`。
- SOCKS 动态转发 `-D`。

### 要求

- 使用现有 `jump_host_id` 关联 Profile，连接前验证跳板 Profile 存在且可用。
- 跳板连接和目标连接状态分开显示。
- 转发规则可保存、启停和删除。
- 转发失败不得关闭已经建立的交互终端，除非底层主连接确实断开。
- 所有转发建立、停止和失败事件写入审计日志。

### 验收标准

- 通过跳板访问内网目标并打开终端/SFTP。
- 本地端口转发可访问内网 HTTP/数据库测试服务。
- 关闭转发后端口释放，重复启用不会产生重复监听。

## 9. P1-2 终端体验

### 必须完成

- xterm.js 尺寸变化同步到远端 PTY 的 rows/cols。
- 终端搜索和搜索结果定位。
- 复制、粘贴、全选、清屏快捷键在 Windows/macOS/Linux 一致。
- 大量输出下不丢数据、不重复追加、不明显阻塞输入。
- 编码至少正确处理 UTF-8、中文和 ANSI 颜色控制序列。
- 断线时保留可复制的最后输出，并显示明确状态。
- 提供本地 Shell 入口，使用平台原生 PTY；本地 Shell 不走 SSH Session。

### 验收标准

- 调整窗口大小后 `stty size` 能返回新尺寸。
- 连续输出 10 MB 文本时输入仍可响应。
- 断线、重连、切换 Tab 不会串写其他 Shell 的输出。

## 10. P1-3 SFTP 增强

### 必须完成

- 多选和批量上传/下载。
- 递归目录上传/下载。
- 隐藏文件显示开关。
- 文件覆盖冲突对话框：覆盖、跳过、重命名、续传。
- 远程文本文件查看，编辑保存作为后续小版本。
- 权限和时间属性展示；权限修改作为后续小版本。
- 失败任务支持批量重试。

### 验收标准

- 目录树和批量传输不会阻塞终端输入。
- 递归传输保留相对目录结构。
- 失败项可单独重试，成功项不会重复上传。

## 11. 主机监控边界

当前监控实现主要依赖 Linux `/proc`、`df`、`ps`。下一阶段要求：

- Linux 继续保持现有字段兼容。
- macOS 增加 `sysctl`、`vm_stat`、`df` 适配。
- BSD/其他 Unix 无法采集时返回“不可用字段”，不得导致 SSH 会话失败。
- 监控 side session 失败只影响监控，不得关闭交互终端。
- 后续再增加历史图表、进程列表和磁盘 I/O。

## 12. 测试和验收矩阵

每个 P0/P1 功能必须同时提供：

- Rust 单元测试。
- 前端状态模型测试。
- 至少一个真实 SSH 集成测试。
- 断线、超时、权限拒绝和重复操作测试。
- Windows、macOS、Linux 平台差异记录。

发布前最低验证：

- 密码登录、私钥登录、Agent 登录。
- known_hosts 首次/匹配/变更/拒绝。
- 跳板机终端和 SFTP。
- 端口转发建立、停止和重启。
- 大文件上传/下载、断网恢复、应用重启恢复。
- 终端 resize、中文、ANSI、10 MB 输出。
- Windows 安装升级；macOS DMG；Linux deb/AppImage。

## 13. 推荐开发顺序

1. 完成 ProxyJump、混合认证和转发 generation 的真实集成验收。
2. 开发 `v0.1.70` 终端 resize、搜索、快捷键和本地 Shell。
3. 完成 TransferDescriptor、持久化队列和重连续传。
4. 完善 SFTP 多选、递归和冲突处理。
5. 完成 macOS/Linux 适配与真实验收。
6. 完成以上基础版本后，再恢复 Agent/MCP 开发。

## 14. 完成定义

当且仅当以下条件全部满足，才可声明“SSH 基础功能完成”：

- P0 项全部通过验收。
- P1 的跳板机、至少一种端口转发和终端 resize 已通过真实环境验证。
- 所有连接状态不会把失败的 side session 误报为主终端断线。
- 关键错误可读、可定位、无敏感信息泄露。
- 三个平台有可重复的构建、安装和回归记录。
